# Rainbow Butterflies — first six-week content and experiment calendar

Status: draft calendar for `rainbow-butterflies/t-008`. **Draft only — no external publication.**
This turns `DESIGN-BRIEF.md`'s six-week release cadence (strategic phases) into a concrete list of
draft content items: what gets written, which content pillar it serves, and roughly when it would
go out *if* the corresponding week's channels are human-approved on schedule. Nothing here creates
an account, claims a handle, or publishes anything — see `LAUNCH-CHECKLIST.md` for the account
prerequisites and `ETHICS.md`/`AUTONOMY.md` for the human gates that still apply to every item
below before it goes anywhere public.

## How to read this calendar

- **Pillar** — one of `DESIGN-BRIEF.md`'s seven content pillars (What the swarm built / AMI
  investigates / Agent collaboration / Creator spotlight / Receipts not hype / The skeptical chair
  / Direct ask), abbreviated below.
- **Channel wave** — which `LAUNCH-CHECKLIST.md` wave the item targets. An item scheduled for a
  wave that isn't approved yet by that week simply waits; the content itself can still be drafted
  ahead of time.
- **Ratio check** — each week's item list is annotated against the DESIGN-BRIEF's ~50/25/15/10
  (useful artifact / collaboration / receipts / direct ask) publishing ratio so no single week
  drifts into a donation-ask-heavy pattern.
- Every item is a **draft** at this stage: a one-line content brief, not finished copy. Writing the
  actual post text happens closer to each week, using `AMI-IDENTITY.md`'s voice guide and
  `ETHICS.md`'s source-standards and disclosure rules at draft time, not calendar time.

## Weeks 1–2 — foundation and build (no publishing)

Per `DESIGN-BRIEF.md`, these two weeks are channel research, the ethics contract, AMI's identity
kit, the commons spec, the README refresh, the site/commons MVP, and the account/handle
checklist — all internal/reversible work with no public posting. Useful content prep that can
happen in parallel without publishing anything:

1. **[What the swarm built]** Draft a "why we're building in public" founding post explaining
   AMI, the commons, and the direct-donation model — held for Week 3's first agent-native post,
   not published early.
2. **[AMI investigates]** Draft one sourced short explainer on how AMF's net-distribution model
   works, using AMF's own published reporting (per `ETHICS.md`'s source standards) — held in
   reserve as a Week 3 or Week 4 mission post.
3. **[Receipts, not hype]** Draft the format for a recurring "build log" post type (what got
   built, what didn't work, one link) so Week 3 onward has a consistent, low-effort template
   rather than improvising structure under time pressure.

No frequency-cap concerns apply yet since nothing publishes in these two weeks.

## Week 6 — first fundraising experiment

Channel wave: all channels approved through Week 5, no new channel added this week — the point is
to run one measurable test on established presence, not to also absorb new-platform overhead.

Pick exactly **one** experiment from `DESIGN-BRIEF.md`'s "Fundraising experiments worth testing"
list, with explicit success/stop criteria decided before it launches (per that section's own
requirement). The two best first-pilot fits, in order of preference:

1. **Butterfly bounties** — lowest setup cost, produces a shareable artifact with contributor
   credit, and exercises the agent-commons contribution loop that Weeks 3–5 have been building
   toward. Recommended first pick.
2. **The useful-object relay** — a good second choice if a concrete Kind Robots object with a
   clean provenance trail is already in progress and ready to be the relay's starting point.

| # | Pillar | Draft brief |
|---|---|---|
| 1 | Agent collaboration | Launch post for the chosen experiment (e.g., post the bounty), stating success/stop criteria up front rather than after the fact. |
| 2 | Receipts, not hype | Mid-week or closing update: fundraiser clicks, contributions, useful conversations generated, and actual donations where independently observable — documenting failure as prominently as success, per `DESIGN-BRIEF.md`. |
| 3 | Direct ask | One direct fundraiser link tied to the finished artifact/result, not a bare ask — "the ask is attached to something the group actually made," per `DESIGN-BRIEF.md`'s useful-object-relay description. |

Ratio for the week: 1 collaboration post, 1 receipts post, 1 direct ask — the receipts post is the
week's centerpiece rather than the ask, consistent with "give before it asks."

## After Week 6

`DESIGN-BRIEF.md` frames Week 6 as ending in a decision: choose what to scale, stop, or redesign.
This calendar deliberately stops at six weeks rather than projecting further — the next calendar
should be written from Week 6's actual results (per `AUTONOMY.md`'s "evidence from a pilot that
requires a specific redesign" as a legitimate reason for new roadmap tasks), not from a schedule
authored before any real engagement data exists.
