**Subject:** Three tasks opened in review on kind_robots PR #1252. Two traps found that will cost the next agent a round-trip if not written down.

**Detail:**

- **`server/utils/entityArt.ts` must NOT be prettier-formatted.** `utils/scripts/verifyEntityArtManager.ts` string-anchors on the exact multi-line shape of its `import type { Prisma, PrismaClient }` statement, and `prettier --write` collapses it to one line, which fails the contract with the unhelpful message "Entity art service TypeScript correction anchors changed." The file already fails `prettier --check` on `main` for exactly this reason. I restored the multi-line form and added a comment saying why. If you touch this file, do not run prettier over it — and if a future change genuinely needs reformatting, update the verifier's anchor in the same commit.

- **`prisma format` reformats files you did not edit.** Running it re-aligned every column in `prisma/facet-catalog.prisma`, which had nothing to do with the change. I reverted that file. Note also that adding a field longer than its neighbours (`allowReviews`) legitimately re-aligns the whole model block, so `git diff --stat` on `schema.prisma` overstates the change — use `git diff -w` to see the real one (135 lines shown, 17 real).

- **The migration was generated without a database.** `prisma migrate diff --from-migrations` needs a shadow DB this sandbox does not have, but `--from-schema <HEAD copy> --to-schema prisma` needs nothing. Export the HEAD versions of all four `prisma/*.prisma` files to a temp dir with `git show HEAD:prisma/<f>` and diff against the working tree. Re-run it after formatting settles and diff against the committed SQL to prove they still match.

- **`icon` is not an art field.** `Bot.icon` / `Character.icon` / `Scenario.icon` / `Dream.icon` / `Project.icon` hold an icon NAME (`'mdi:radio-tower'`), not a path. Project's art registry maps `imagePath` to the 256px "Icon" slot instead. I added `icon` columns for nav/badge use but deliberately kept them out of `ENTITY_FIELDS`. Do not "fix" that by adding an icon art slot.

- **Pre-existing red left alone, deliberately.** eslint reports two errors on `main` in files this PR touches: `server/api/rewards/index.ts:3` ("Prisma only used as type") and `server/utils/entityArt.ts` (empty catch block). Both predate this work and both are left as-is to keep the diff scoped. Flagging so the next agent does not think this PR introduced them.
