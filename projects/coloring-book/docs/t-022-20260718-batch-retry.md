# Monster Recast batch retry — 2026-07-18

## Resolution — 2026-07-20

The sidecar coloring-art event bridge has been retired. It duplicated the real ArtJob queue, retried the same pending batch on an hourly schedule, and produced repeated failures without landing renders.

`projects/coloring-book/color-art-jobs.yaml` is now the sole repository-side source of truth. The existing `Coloring Book ArtJobs` workflow submits pending entries to the Kind Robots ArtJob API and lands completed renders back into the repository.

The deleted event reached 30 attempts. Those attempts proved that event parsing and submission were functioning, but the downstream ArtJob/render pipeline was not completing the jobs.

## Operating model

- Add, approve, or revise coloring work only in `projects/coloring-book/color-art-jobs.yaml` and the proposal ledgers it references.
- Do not create a second `color-art-events` queue or a dedicated event processor.
- Queue changes may trigger the existing ArtJobs workflow; manual dispatch remains available for controlled retries.
- The ArtJob service owns durable claiming, stale-claim recovery, attempts, and completion state.
- A timed-out submitter run must not be treated as permission to enqueue the same concepts on a recurring schedule.

## Current infrastructure gate

Before manually retrying the pending Monster Recast batch, verify that the Alexandria relay, ComfyUI worker, and Kind Robots database path are healthy. The previous failures were downstream of submission, not failures in the coloring-book queue definition.
