# Pack manifest schema (v1)

Generated by: packmaker/t-002. Builds directly on `SPEC.md` §1 (item-type →
kind_robots model mapping), §2 (generation pipelines), §4 (interim
visibility rule), §5 (digital-storefront entitlement mapping), and §7 (open
question on character item shape).

A pack manifest is a single YAML file in this directory (`projects/packmaker/packs/*.yaml`).
One file = one pack. `example-starter-pack.yaml` in this directory is a
worked example that validates against this schema.

This schema is a **draft-tracking format**, not a generation trigger — writing
or editing a manifest performs no generation, API calls, or database writes.
Manifests describe what a pack contains and its current progress toward
generation; the admin generator (t-004) reads a manifest and drives §2's
pipelines against it.

## Top-level fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `schemaVersion` | integer | yes | `1` for this version. Bump on breaking changes to this file's shape; the admin generator (t-004) should refuse to load a manifest whose `schemaVersion` it doesn't recognize rather than guess. |
| `id` | string (kebab-case slug) | yes | Unique pack slug, e.g. `uncanny-valor`. Matches the manifest filename's stem (`uncanny-valor.yaml`). Becomes `Product.metadata.packSlug` once a digital-storefront `Product` row exists for this pack (SPEC §5). |
| `title` | string | yes | Display title, e.g. "Uncanny Valor". |
| `description` | string | yes | Short pack summary for browse/preview surfaces. |
| `owner` | string | yes | `userId` the pack's draft items are created under (SPEC §4's interim rule: all items are `isPublic: false`, tied to this owner, until released). Use `"silas"` as a placeholder until real per-pack ownership is wired to an actual account id. |
| `visibility` | enum: `draft` \| `released` | yes | Interim, all-or-nothing switch per SPEC §4 (no per-purchaser grant model exists until kind-robots t-008 lands). `draft` → every item's `isPublic` stays `false`. `released` → every item's `isPublic` flips to `true`. There is no partial-release state in v1. |
| `price` | object | yes | See **Price hook** below. |
| `items` | list of item objects | yes | See **Item entries** below. At least one entry. |

## Price hook

```yaml
price:
  hook: free | one-time | dlc
  productSlug: <string, optional>
```

- `hook` — how the pack maps to a digital-storefront `Product` (SPEC §5). `free`: no purchase gate, visible to anyone once `visibility: released`. `one-time`: a single-purchase digital good. `dlc`: purchasable content gated behind an `Entitlement` row — the same `Product`/`Entitlement` shape digital-storefront already designed for the Mermaids of Venice PDF (SPEC §5), no pack-specific entitlement mechanism.
- `productSlug` — set once digital-storefront creates the matching `Product` row for this pack (`type: DLC`, `metadata: { packSlug: id }`). Omit while no `Product` row exists yet; packmaker does not create `Product` rows itself, digital-storefront/t-017 does.

## Item entries

Each entry in `items` is one pack content item:

```yaml
items:
  - id: <string>
    type: location | genre | character | reward
    itemShape: dream | facet | character | reward
    refId: <integer, optional>
    draftPayload:
      title: <string>
      description: <string>
      generationPrompt: <string>
      artPrompt: <string>
    notes: <string, optional>
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string (kebab-case slug) | yes | Unique within this pack only (not globally). Used for manifest-internal references and admin-UI listing. |
| `type` | enum: `location` \| `genre` \| `character` \| `reward` | yes | The pack-facing content category, per SPEC §1's table. |
| `itemShape` | enum: `dream` \| `facet` \| `character` \| `reward` | yes | The actual kind_robots model this item becomes once generated. Usually implied by `type` (`location` → `dream`, `genre` → `facet`, `reward` → `reward`) — spelled out explicitly rather than inferred so a manifest can answer SPEC §7's open question per item: a `character`-type entry may choose `itemShape: dream` (`dreamType: CHARACTER`, lore-only) or `itemShape: character` (the standalone `Character` model with stat blocks), per pack. |
| `refId` | integer | no | The generated row's primary key once this item has been created and persisted (e.g. a `Dream.id`). Omit entirely while the item is still a draft — do not use `null` as a stand-in for "not generated yet" (see the schema-parity/sentinel convention in the top-level `CLAUDE.md`: absence means "not generated", not an empty/failed value). |
| `draftPayload` | object | required while `refId` is unset | The plain-payload fields the target model needs before generation. Required sub-fields: `title`, `description`, `generationPrompt` (drives the text-gen call, SPEC §2), `artPrompt` (drives the art-gen call, SPEC §2). Once `refId` is set, `draftPayload` may be dropped (the real row is now the source of truth) or kept as a record of the original brief — either is valid, the admin generator should not require its absence. |
| `notes` | string | no | Free-form authoring notes (e.g. "swap art style once t-005 curriculum lands"). Never consumed by generation. |

## Versioning

This file documents `schemaVersion: 1`. A future breaking change (renamed
field, changed enum, new required field) increments `schemaVersion` and
should keep this file's old-version section (or a linked prior revision)
so the admin generator (t-004) can still read older manifests during a
migration window — mirroring the "prior default preserved" convention used
elsewhere in this codebase family (see PortOS's `PREVIOUS_DEFAULT_PROMPTS`
pattern) rather than breaking existing pack files outright.
